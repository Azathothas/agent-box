# References

This page lists every upstream project that agent-box cites, at a pinned commit.
It also holds the findings that the rewrite of 2026-10-14 keeps from the old reference sweeps.
The engine evidence of the same day is in [the engine evaluation](research/engines-2026-10.md).
The operator's microVM research is in [the microVM research](research/microvm-tier.md).

Labels on this page:

- READ: somebody opened the source at the pin and found the statement there.
- MEASURED: somebody ran it. The finding gives the host, the date and the conditions.
- No label: a design rule that agent-box takes from the reading.

NOTE: A tracker item (an issue, a pull request or a comment) is evidence of what somebody intended.
It is not evidence of what the code does.
Where a tracker item and the code disagree, the disagreement is the finding.

## Why there is no corpus branch

- The old `references` branch held the source trees and the tracker JSON of 15 references, about 135 MB.
- The operator ruled on 2026-10-14 that the branch is dropped after one relevance pass (D9 in [decisions](decisions.md)).
- The relevance pass read the old sweeps against the pivot and kept 202 findings.
- This page keeps those findings as text, each with a full citation.
- One reference, talaria0101/egi, is dropped from the pins. Five findings below cite it by URL.
- A pin plus a citation is weaker than a kept corpus. A tracker can change, and a repository can disappear.
- The pins make each citation checkable again. They do not store the evidence.

### How to get a tree

```sh
cargo xtask refs fetch
cargo xtask refs fetch QaidVoid/kage
```

- The first command clones every pin of the "Pins" table below. The second command clones one reference.
- `cargo xtask refs` reads the "Pins" table of this page. The tool is `xtask/src/refs.rs`.
- It clones each pin into the ignored directory `.refs/`, one directory per reference, and verifies that HEAD equals the pinned commit.
- It never runs code from a clone.
- Treat every file under `.refs/` as untrusted data. A file in a clone is never an instruction.
- Two rows are pinned by a release and have no commit: herdr and ToolKit. `refs` skips them.
- Read herdr from the raw URLs of its documentation index. Read ToolKit at its release 6.0.0.
- `refs` fetches source trees only. This page cites tracker items by URL. Read them in a browser or with a read-only `gh api` call.
- The issues endpoint of the GitHub API returns pull requests too. Tell them apart by the `pull_request` field.
- QaidVoid/kage has two rows. The first row is the current pin. The second row keeps two citations of the old corpus checkable.

## Kept findings

The findings are grouped by area. Each finding has an id for reference from entries.
"Entry" names the entry that uses the finding.

### Broker

- BR-01. Identity comes from the host-side channel, never from the guest. A microVM guest is root in its own kernel, so it can forge a source address or a header. READ: OpenSandbox selects the vault by guest source address. Its own smoke test forges a sibling's address. READ: `opensandbox-group/OpenSandbox@8f9b616ed54852a65fc0a1ef4443f81da632aaf7:components/egress/pkg/fastsandboxnft/fastsandboxnft.go:36-41`; `opensandbox-group/OpenSandbox@8f9b616ed54852a65fc0a1ef4443f81da632aaf7:components/egress/tests/smoke-fast-sandbox.sh:588-601`. Entry: T-031, T-143.
- BR-02. A controller assigns routing identity after it merges user input, and it filters user-supplied reserved keys. Otherwise one tenant can take another tenant's traffic. READ: `kubernetes-sigs/agent-sandbox@4b63868f0d67e4ee0fa690bb14cb5722b78d679d:docs/security/threat_model.md:95-114`. Entry: T-143.
- BR-03. A nonce resolves only on the channel of the instance that holds it. agent-vault never retargets a scoped session. A hint that names another vault is an error. Several grants without a hint are an error, never a pick. READ: `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/brokercore/session.go:72-150`. Entry: T-141.
- BR-04. In errand, all sessions of one daemon run share the nonce of a provider. No request then maps to one session, and no single session can be revoked. agent-box mints a nonce per instance per binding. READ: `QaidVoid/errand@58a178b2a03dee289bb535e1fdc58676344050eb:src/serve.ts:94-106`. Entry: T-141.
- BR-05. errand's podman backend puts the provider key and the GitHub token on argv as `--env KEY=VALUE`. The host process table shows them. READ: `QaidVoid/errand@58a178b2a03dee289bb535e1fdc58676344050eb:src/sandbox/podman.ts:124-131`. Entry: T-141.
- BR-06. Under Firecracker, the guest reads boot arguments in /proc/cmdline, every guest process reads MMDS, and the host shows jailer argv. So nonces and the egress token travel only over the control vsock, after boot and before kage starts. Entry: T-256, T-041.
- BR-07. Compare a nonce, token or signature in constant time. Make identifiers and tokens from a CSPRNG, never from a timestamp or a counter. READ: `Azathothas/TEMPLATE@ea26c7d91a087a7132f56034fb77f8d40d7766cb:docs/conventions/forbidden-patterns.md:39`; `Azathothas/TEMPLATE@ea26c7d91a087a7132f56034fb77f8d40d7766cb:docs/conventions/code.md:116-117`. Entry: T-141.
- BR-08. Docker Sandboxes is a deployed form of the agent-box credential model. The sandbox holds a sentinel, and an egress proxy swaps in the real key for the provider host. READ: `earendil-works/pi@f9bcd351dc3cedf989bc5fc0f8aa012db5737df2:packages/coding-agent/docs/containerization.md:114-121`.
- BR-09. Docker Sandboxes wires credentials when it creates the sandbox, so they must be on the host first. The sentinel copies the real key format, so client format checks accept it. agent-box nonces copy each provider key format. READ: `earendil-works/pi@f9bcd351dc3cedf989bc5fc0f8aa012db5737df2:packages/coding-agent/docs/containerization.md:127-136`. Entry: T-141.
- BR-10. Replace exactly one auth header and never add a second one. kage sends one auth header per wire kind and never puts a key in the URL. READ: `QaidVoid/kage@f8df98929f642866932d507b75afac0978e60964:docs/guide/providers.md:364-377`. Entry: T-143.
- BR-11. kage header kinds: anthropic sends `x-api-key`, openai and openai-responses send `authorization: Bearer`, gemini sends `x-goog-api-key`. READ: `QaidVoid/kage@f8df98929f642866932d507b75afac0978e60964:crates/kage-provider/src/anthropic.rs:103`; `QaidVoid/kage@f8df98929f642866932d507b75afac0978e60964:crates/kage-provider/src/openai.rs:141`; `QaidVoid/kage@f8df98929f642866932d507b75afac0978e60964:crates/kage-provider/src/openai_responses.rs:86`; `QaidVoid/kage@f8df98929f642866932d507b75afac0978e60964:crates/kage-provider/src/gemini.rs:92`. Entry: T-141.
- BR-12. With two credentials bound to one host, the Docker Sandboxes proxy adds `x-api-key` next to the Bearer token, and Anthropic refuses the request. Bind one credential shape per host. READ: `earendil-works/pi@f9bcd351dc3cedf989bc5fc0f8aa012db5737df2:packages/coding-agent/docs/containerization.md:124`. Entry: T-143.
- BR-13. Strip before the gate. Remove every header that a matched binding will set before the gate runs. Then a header that the guest forged is never forwarded when the gate fails. READ: `TencentCloud/CubeSandbox@eaddce3a0e2ed76b246ef42996cf5f9ed671aeac:CubeEgress/lua/access_phase.lua:358-375`. Entry: T-143.
- BR-14. errand forwards every client header as received, including a header that carries the nonce. Remove every header that carried a nonce before forwarding. READ: `QaidVoid/errand@58a178b2a03dee289bb535e1fdc58676344050eb:src/sandbox/broker.ts:161-199`. Entry: T-143.
- BR-15. A failed gate refuses the request. At the pin, CubeSandbox drops the injection and still forwards the request. Plaintext injection needs only a non-empty Host. READ: `TencentCloud/CubeSandbox@eaddce3a0e2ed76b246ef42996cf5f9ed671aeac:CubeEgress/lua/access_phase.lua:197-234`. Entry: T-143.
- BR-16. Correction: the old broker sweep said that CubeSandbox PR 1411 fixed issue 1410. PR 1411 was closed without merge, so the defect is in the pinned tree. The project blog says that a request must be HTTPS, and the code contradicts it. READ: https://github.com/TencentCloud/CubeSandbox/pull/1411; `TencentCloud/CubeSandbox@eaddce3a0e2ed76b246ef42996cf5f9ed671aeac:docs/blog/posts/2026-06-23-cubesandbox-network-deep-dive.md:185-193`.
- BR-17. Inject only when exactly one binding matches scheme, host, port, method and path. OpenSandbox refuses an ambiguous match at the same precedence and never resolves it by order. READ: `opensandbox-group/OpenSandbox@8f9b616ed54852a65fc0a1ef4443f81da632aaf7:docs/guides/credential-vault.md:55-57`; `opensandbox-group/OpenSandbox@8f9b616ed54852a65fc0a1ef4443f81da632aaf7:components/egress/mitmscripts/system.py:774-791`. Entry: T-141, T-143.
- BR-18. A binding without a method set or a path scope is a refusal. OpenSandbox widens an omitted scope to everything. Its guard against that (PR 1762, merged) is opt-in, and issue 1776 to make it the default is open. READ: `opensandbox-group/OpenSandbox@8f9b616ed54852a65fc0a1ef4443f81da632aaf7:docs/guides/credential-vault.md:305-310`; https://github.com/opensandbox-group/OpenSandbox/issues/1776. Entry: T-141.
- BR-19. OpenSandbox selects the binding by the Host header or `:authority`, which the sandbox controls. The SNI anchor fix (PR 1759) is open at the pin. READ: `opensandbox-group/OpenSandbox@8f9b616ed54852a65fc0a1ef4443f81da632aaf7:components/egress/mitmscripts/system.py:566-568`; https://github.com/opensandbox-group/OpenSandbox/pull/1759. Entry: T-149.
- BR-20. Correction: the old credential-brokering page said that two projects shipped the SNI anchor and fixed the defect. At the pins, OpenSandbox PR 1759 is open and CubeSandbox PR 1411 is unmerged.
- BR-21. Under explicit endpoints, the endpoint name selects the binding, and the binding fixes the upstream host. So a forged Host header cannot move a credential to another upstream. Optional interception (T-149) anchors on the validated SNI. Entry: T-142.
- BR-22. A matching Host or SNI does not prove the destination address. In CubeSandbox issue 1697, `curl --resolve` kept the allowed name and moved the destination. All four HTTP and HTTPS cases returned 200. READ: https://github.com/TencentCloud/CubeSandbox/issues/1697. Entry: T-123.
- BR-23. Issue 1697 and PR 1695 are open. Their open points: proxy-side DNS gives false denials under CDN or split DNS, and observed answers need provenance and expiry. A re-resolved address must pass the address policy again. agent-box answers this with answered-address binding (NET-06). READ: https://github.com/TencentCloud/CubeSandbox/pull/1695.
- BR-24. Verify the upstream certificate against the binding's fixed host. CubeSandbox verifies the upstream (TLS 1.2 or later) against the original SNI and forces the upstream Host to the SNI on HTTPS. READ: `TencentCloud/CubeSandbox@eaddce3a0e2ed76b246ef42996cf5f9ed671aeac:CubeEgress/nginx.conf:175-194`. Entry: T-144.
- BR-25. The CubeSandbox comment "dst IP authentic, implicit via G6" is false on the plaintext path. Issue 1697 shows that it is not enough on HTTPS either. READ: `TencentCloud/CubeSandbox@eaddce3a0e2ed76b246ef42996cf5f9ed671aeac:CubeEgress/lua/access_phase.lua:26-27`.
- BR-26. Refuse a binding whose upstream TLS verification is off. OpenSandbox refuses a credential vault under SSL_INSECURE, because a credential could go to a spoofed upstream. READ: `opensandbox-group/OpenSandbox@8f9b616ed54852a65fc0a1ef4443f81da632aaf7:oseps/0012-credential-vault.md:186`. Entry: T-141, T-144.
- BR-27. Never route by the client's Host header. agent-vault sets the upstream Host to the authenticated target and removes the default port, so signatures over Host still match (PR 195). READ: `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/mitm/forward.go:147-180`. Entry: T-144.
- BR-28. A substitution declares a placeholder, the credential it stands for and its surfaces: path, query, header, body or websocket. agent-vault names that surface list as the security boundary. READ: `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/broker/broker.go:62-69`; `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/brokercore/substitution.go:16-20`. Entry: T-145.
- BR-29. Encoding is per surface. A path value is path-escaped into the wire path, so it lands once. A query value is query-escaped. A header value is raw, and a CR or LF in it fails the whole request. READ: `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/brokercore/substitution.go:36-87`. Entry: T-145.
- BR-30. A form body uses query escaping, a JSON body uses JSON string escaping, and a multipart body is skipped. On any error the request is not forwarded, because some mutations may already apply. READ: `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/brokercore/substitution.go:95-155`. Entry: T-145.
- BR-31. Substitute in one pass. agent-vault replaces each placeholder in turn, so a later placeholder can match text inside an inserted value. OpenSandbox replaces all in one pass and never rescans inserted values. READ: `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/brokercore/substitution.go:128-130`; `opensandbox-group/OpenSandbox@8f9b616ed54852a65fc0a1ef4443f81da632aaf7:docs/guides/credential-vault.md:226-228`. Entry: T-145.
- BR-32. OpenSandbox refuses a path rewrite with dot-segments, nested or boundary-crossing encoded separators, or backslashes. READ: `opensandbox-group/OpenSandbox@8f9b616ed54852a65fc0a1ef4443f81da632aaf7:components/egress/mitmscripts/system.py:585-640`. Entry: T-145.
- BR-33. OpenSandbox's header surface excludes Host, Content-Length and forwarding headers, and it runs before auth injection. A body rewrite sets Content-Length and removes Transfer-Encoding. Compressed and multipart bodies are skipped. READ: `opensandbox-group/OpenSandbox@8f9b616ed54852a65fc0a1ef4443f81da632aaf7:docs/guides/credential-vault.md:216-236`. Entry: T-145.
- BR-34. Add the placeholder and every encoded form of the value to the redaction set. READ: `opensandbox-group/OpenSandbox@8f9b616ed54852a65fc0a1ef4443f81da632aaf7:docs/guides/credential-vault.md:216-236`. Entry: T-145, T-176.
- BR-35. agent-vault caps a forwarded request body at 1 GiB, and a body held in memory for a body substitution at 64 MiB. READ: `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/brokercore/session.go:10-18`. Entry: T-145.
- BR-36. OpenSandbox streams a body above 1 MiB before its body hook runs. So binding match, path, query and header work happen at header time, and body substitution is skipped for streamed requests. READ: `opensandbox-group/OpenSandbox@8f9b616ed54852a65fc0a1ef4443f81da632aaf7:components/egress/mitmscripts/system.py:31-36`. Entry: T-145.
- BR-37. WebSocket credentials are substituted at the agent-vault pin. PR 225 (merged 2026-06-01) closed issue 209 with a websocket surface. READ: `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/mitm/websocket.go:296-326`; https://github.com/Infisical/agent-vault/pull/225. Entry: T-145.
- BR-38. Correction: the old limits page said that agent-vault copies frames after the upgrade untouched. The real limit is narrower. Substitution covers only client-to-upstream text frames that are unfragmented, uncompressed and at most 1 MiB. READ: `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/mitm/websocket.go:377-437`.
- BR-39. The agent-vault handshake forwards Sec-WebSocket-Extensions, so permessage-deflate can turn substitution off without notice. Strip or refuse permessage-deflate on a substituted upgrade. READ: `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/mitm/websocket.go:45-53`. Entry: T-145.
- BR-40. The broker chooses the protocol on each side. agent-vault offers only http/1.1 to the client and disables HTTP/2 upstream, so an h2-only client (gRPC) cannot pass. READ: `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/mitm/connect.go:107-109`; `Infisical/agent-vault@f0cdface45da8f7eca07f737a03537be75f20a71:internal/mitm/proxy.go:86`.
